# 配置平台网页端

`docs/` 是可直接部署到 GitHub Pages 的静态网页版本。它使用手机浏览器调用 GitHub Contents API，支持：

- 管理多个 GitHub 仓库连接
- 读取、创建、编辑和删除应用 JSON 配置
- 应用总开关、版本、支付套餐、广告位和功能开关
- 其他字段、完整 JSON 文本配置、预览和请求测试
- 连接配置导入与导出

应用列表和应用详情使用浏览器内路由分开显示：点击应用后会进入全屏详情页，地址会带有 `#app=...`，刷新后仍会恢复当前应用；点击详情页左上角的“应用列表”即可返回。

网页端不包含 IPA 打包或安装功能。

## JSON 空字段处理

新建、保存及预览应用配置时，递归省略空字符串（含纯空白）、`null`、空数组和内容全部为空的对象。例如 `taku` 中所有字段为空时，输出 JSON 不包含 `taku`；只填写 `appid` 时，仅输出 `taku.appid`。`revenue`、`paylist`、`switch`、`other` 和自定义字段采用相同规则。数字 `0`、布尔值 `false` 和非空内容会保留，表单仍可继续编辑被省略的配置项。

当前版本为非必填。版本为空（含纯空白）或缺失时，输出 JSON 省略整个 `app` 字段，包括其中的 `ad`、`on`；填写版本后保留 `app`，并检查版本格式。

## 通用配置与发布版本

每个应用的基础文件是通用 JSON，例如 `a.json`。在应用编辑页的“版本发布”区域创建版本 `1.0` 后，平台会创建带有该版本 SHA-256 十六进制摘要的文件，例如 `a<sha256(1.0)>.json`，并登记到 `peizhi.json`。文件名只包含英文字母和数字。新版本默认处于“审核中”，文件只保留通用 JSON 的 `paylist` 字段。

点击“上线版本”后，平台会重新读取通用 JSON，将完整内容复制到对应版本文件；点击“退回审核”则会再次把版本文件收敛为只包含 `paylist`。通用 JSON 始终保留完整配置，版本切换不会修改通用文件。

版本发布区域会以独立标题显示，并按行列出全部版本，每个版本明确显示“审核中”或“已上线”。每个版本都可以修改、预览、测试请求、上线/退回审核或删除；修改版本会打开该版本自己的 JSON，保存时不会覆盖通用 JSON。已上线版本修改 `app.version` 后，JSON 中的版本值和版本登记会同步更新；审核中版本仍只保留 `paylist`，不会写入版本号。

点击“同步全部版本”会把通用 JSON 的最新内容同步到所有版本：已上线版本同步完整配置并保留各自版本号，审核中版本只同步 `paylist`。

此规则在下次保存配置时生效，已有远程 JSON 不会自动批量改写。应用目录 `peizhi.json` 和连接配置不受影响。

运行回归检查：`node --test tests/*.test.js`。

## 部署

1. 将仓库推送到 GitHub。
2. 在仓库的 **Settings → Pages** 中选择 **Deploy from a branch**。
3. 选择需要发布的分支，并将目录设为 `/docs`。
4. 打开 GitHub Pages 地址，在手机浏览器中使用。

首次使用时点击“连接管理”，填写 GitHub Fine-grained token 和仓库地址（例如 `owner/repo`）。令牌只保存在当前浏览器的本地存储中，网页不会把令牌上传到其他服务器。

建议令牌只授予目标私有仓库的 Contents 读写权限，并为 GitHub Pages 配置 HTTPS 地址后再使用。
